# Промо-акция «Чек на удачу»

Веб-сервис для проведения маркетинговой промо-акции бренда с регистрацией и модерацией кассовых чеков согласно требованиям **54-ФЗ**.

---

## Стек технологий

- **Backend:** Python 3.14, Django 6.0, Gunicorn
- **Database:** PostgreSQL 17
- **Package Manager:** [uv](https://github.com/astral-sh/uv) (Astral)
- **Infrastructure:** Docker, Docker Compose, Nginx (reverse-proxy, раздача статики, микрокеширование)
- **CI/CD:** GitHub Actions (автоматический деплой на VPS)
- **Frontend:** Vanilla JS (без сторонних фреймворков), HTML5 / CSS3 (Pixel-Perfect по Figma, мобильная адаптивность от 375px)

---

## Архитектура и ключевые особенности

1. **Кастомная модель пользователя (`accounts.User`):**
   - На базе `AbstractUser` для безопасного масштабирования профиля без рискованных миграций дефолтной таблицы auth в будущем.
2. **Фискальная модель чека (`receipts.Receipt`):**
   - Поля по 54-ФЗ: `fn` (16 цифр), `fd` (до 10 цифр), `fp` (до 10 цифр), `purchase_date`, `total_amount`.
   - Уникальное ограничение на уровне СУБД: `models.UniqueConstraint(fields=['fn', 'fd', 'fp'])`.
3. **Модерация чеков (Django Admin):**
   - N+1 оптимизация (`list_select_related = ('user',)`).
   - Валидация отклонения: статус «Отклонен» не может быть сохранен без указания причины отказа.
   - Экспорт принятых чеков в CSV с UTF-8 BOM (`\ufeff`) для корректного открытия кириллицы в Microsoft Excel.
4. **Клиентский UX / UI:**
   - Быстрый парсинг строки QR-кода (`t=...&s=...&fn=...&i=...&fp=...`) через стандартный `URLSearchParams` с автозаполнением формы.
   - Асинхронная отправка формы через `fetch` без перезагрузки страницы с обработкой серверных ошибок валидации.
   - Автоматический polling статусов каждые 20 секунд для чеков в состоянии «На проверке».
   - Мобильная адаптивность: плавное переключение таблицы личного кабинета в карточный вид.

## Спорные моменты и архитектурные решения

### 1. Проблема 11 часовых поясов РФ
Кассовые чеки по 54-ФЗ содержат наивное локальное время кассы (`t=YYYYMMDDTHHMM`) без указания таймзоны.
- **Период акции:** Чтобы покупатели из Калининграда (UTC+2) и Камчатки (UTC+12) были в равных условиях, проверка попадания в акцию проводится по местному календарному дню покупки (`promo_start.date() <= purchase_date.date() <= promo_end.date()`).
- **Защита от чеков «из будущего»:** Время чека сравнивается с текущим временем в самом восточном поясе РФ (Камчатка, опережает московское время на 9 часов: `moscow_now + 9 hours`). Чек считается невалидным только если он выбит позже, чем время наступило в самой дальней точке страны.

### 2. Уникальность чека и повторная регистрация
Связка `ФН + ФД + ФП` уникальна в масштабах страны.
- При повторной попытке зарегистрировать чек форма перехватывает дубликат до обращения к базе и отдает понятную ошибку пользователю с HTTP 400 (предотвращая необработанный сбой СУБД 500).
- Отклоненные чеки остаются в базе и не могут быть зарегистрированы повторно тем же или другим пользователем во избежание спама невалидными данными.

## Быстрый старт

### 1. Запуск через Docker Compose (рекомендуется)

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/itskeimy/test_task_first.git
   cd test_task_first
   ```

2. Скопируйте файл переменных окружения:
   ```bash
   cp .env.example .env
   ```

3. Запустите стек контейнеров:
   ```bash
   docker compose up -d
   ```
   Сервис будет доступен по адресу `http://localhost:8099`.

4. Создайте суперпользователя для доступа в панель управления:
   ```bash
   docker compose exec web python manage.py createsuperuser
   ```

---

### 2. Локальный запуск для разработки

Требуется установленный Python 3.12+ и [uv](https://docs.astral.sh/uv/):

1. Установите зависимости:
   ```bash
   uv sync
   ```

2. Настройте локальную БД PostgreSQL (или используйте параметры из `.env`):
   ```bash
   cp .env.example .env
   ```

3. Примените миграции:
   ```bash
   uv run python manage.py migrate
   ```

4. Запустите сервер разработки:
   ```bash
   uv run python manage.py runserver
   ```
   Сервис доступен по адресу `http://127.0.0.1:8000`.

## Тестирование

Тестовый сьют разделен на изолированные модули в директориях `receipts/tests/` и `accounts/`:
- `receipts/tests/test_forms.py` — валидация сумм, дат, таймзонных сдвигов Камчатки, длин реквизитов и дубликатов.
- `receipts/tests/test_views.py` — авторизация, редиректы, изоляция данных кабинета, граничные случаи пагинации (10 и 11 чеков).
- `receipts/tests/test_api.py` — соответствие спецификации JSON, постраничная навигация, изоляция API между пользователями.
- `receipts/tests/test_admin.py` — логика модерации, обязательность причины отказа, экспорт в CSV с UTF-8 BOM.
- `accounts/tests.py` — регистрация с автологином, валидация паролей, редиректы и сценарии входа/выхода.

Запуск всех тестов:
```bash
uv run python manage.py test -v 2
```
